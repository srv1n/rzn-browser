# RZN-T-0011 · Restart the supervisor during runtime upgrades

## Intent

Write a few plain sentences a former product manager can read cold — no file
names, symbols, or commands here; those live in the appendix below.

- What this is: Make runtime upgrades replace the process as well as its files.
- Why it matters: A stale background process can reject the newly installed client and break every browser workflow.
- What "done" looks like: An upgrade stops a healthy running supervisor, installs the new runtime, and starts the supervisor again. An incompatible live supervisor blocks the upgrade before files are replaced.

## Acceptance

| ID | Outcome | Proof |
|---|---|---|
| A1 | A release upgrade stops the old supervisor and starts the installed supervisor. | Focused release-installer test. |
| A2 | An unauthenticated live supervisor blocks replacement instead of leaving mixed old-process/new-file state. | Installer control-flow review and shell validation. |

## Non-goals

- Changing browser workflow behavior.
- Retrying failed ChatGPT submissions.
