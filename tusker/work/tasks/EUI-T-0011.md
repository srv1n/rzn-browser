# EUI-T-0011 · Redesign extension UI and workflow catalog

## Intent

Replace the dashboard and popup's heavy card-based dark UI with a restrained system-native interface that follows the operating-system color scheme. Make the workflow catalog usable at scale through grouping, search, filters, and compact tables while preserving existing actions and RPC behavior.

## Acceptance

| ID | Outcome | Proof |
|---|---|---|
| A1 | Dashboard and popup use system fonts, semantic controls, responsive layouts, and automatic light/dark colors through `prefers-color-scheme`. | Extension build and source inspection |
| A2 | Workflows are grouped by workflow namespace and can be searched and filtered by health and source without losing run-now or parameter entry. | Focused DOM and helper tests |
| A3 | Runs, Fleet, Logs, and Settings retain their data, actions, empty/error states, and become visually consistent tables/forms. | Full extension unit suite |
| A4 | Chrome/Edge/Chromium/Firefox extension bundles compile and the installed Chrome bundle is refreshed. | Extension build and bundle hash check |
| A5 | Workflow run panels render typed, labeled fields from each manifest's parameter schema, mark required inputs, apply defaults and constraints, and submit normalized values without exposing raw JSON. | Supervisor and focused DOM tests |

## Non-goals

- Do not add a UI framework, icon library, custom theme toggle, gradients, or ornamental illustrations.
- Do not change supervisor RPC contracts or runtime behavior.
- Do not redesign the browser automation content overlay.
